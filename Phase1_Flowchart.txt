1. PHASE 1 SYSTEM ARCHITECTURE
=====================================================================

            +-----------+   +-----------+   +-----------+
            |  Student  |   |  Teacher  |   |   Admin   |
            +-----+-----+   +-----+-----+   +-----+-----+
                  |               |               |
                  +-------+-------+-------+-------+
                          |  HTTPS
                          v
   +=========================================================+
   |        ONE SERVER (2 vCPU, 4-8 GB RAM) - Docker         |
   |                                                         |
   |   [Nginx] SSL + reverse proxy                           |
   |      |                                                  |
   |      +--> [Next.js Frontend]  (student + admin UI)      |
   |      |                                                  |

   |               |          questions, review, download)   |
   |               |                                         |
   |               +--> [PostgreSQL]  all structured data    |
   |               |                                         |
   |               +--> [Redis] --> [BullMQ queue]           |

                |                              |

   |  Object Storage         |     |  LLM API (vision)      |

2. LOGIN & ROLE FLOW
=====================================================================

   [User opens app]
          |
          v
   < Has account? > --No--> < Role? >
          |                    |
         Yes                   +-- Student --> [Self signup / school invite]
          |                    |                        |
          |                    +-- Teacher/Admin --> [Invite only by
          |                                           Super Admin]
          |                                             |
          v                                             v
   [Login: email + password]  <-------------------------+
          |
          v
   [NestJS verifies] --> [Issue JWT access token + refresh token]
          |
          v
   < Role in token? >
          |
          +-- SUPER ADMIN --> [Admin panel + settings: curriculum,
          |                    levels, subjects, topic tree, users]
          +-- ADMIN -------> [Admin panel: upload, review queue,
          |                    approve/publish, archive]
          +-- TEACHER -----> [Teacher panel: upload, review &
          |                    correct, submit for approval]
          +-- STUDENT -----> [Student app: browse, reveal answer,
                               bookmark, download, report issue]

   Every API request:
   [Request + JWT] --> [Auth guard] --> [Role guard] --> < Allowed? >
                                                           |      |
                                                          Yes     No
                                                           |      |
                                                     [Handle]  [403]

   (S) JWT is stateless -> any number of API servers can verify it.
       No change needed when scaling.

          |

          |                     |
         Yes                    No
          |                     |
          v                     v

    "Paper exists"]             |
                                v
                         [Create paper row in DB

                                |

4. AI PROCESSING PIPELINE (BACKGROUND WORKER)
=====================================================================

   [Worker picks "process-paper" job]
          |
          v
   [Status = PROCESSING, progress 0%]
          |
          v
   [Download PDFs from S3/R2]
          |
          v
   [PDF library (no AI)]
     - render every page as high-res image
     - extract text layer (if digital PDF)
     - extract embedded images
          |
          v
   +-----------------------------------------------------------+
   |  FOR EACH PAGE (or group of pages) of QUESTION PAPER      |
   |                                                           |
   |  [Send to Vision LLM]                                     |
   |    input : page image + extracted text +                  |
   |            fixed topic list for this subject              |
   |    output: JSON per question                              |
   |      - question number (14, 14a, 14b...)                  |
   |      - type (MCQ / THEORY / STRUCTURED)                   |
   |      - marks                                              |
   |      - text with LaTeX equations                          |
   |      - MCQ options A/B/C/D (if MCQ)                       |
   |      - diagram box coordinates                            |
   |      - topic, subtopic, difficulty                        |
   |      - confidence scores                                  |
   |          |                                                |
   |          v                                                |
   |  < Valid JSON & topic in allowed list? >                  |
   |          |                 |                              |
   |         Yes                No --> [Retry once] --> still  |
   |          |                         fails? mark question   |
   |          |                         "NEEDS_MANUAL"         |
   |          v                                                |
   |  [Crop diagram from page image using box]                 |
   |  [Convert to WebP] --> [Save to S3/R2]                    |
   |          |                                                |
   |          v                                                |
   |  [Update progress %]                                      |
   +-----------------------------------------------------------+
          |
          v
   +-----------------------------------------------------------+
   |  MARK SCHEME                                              |
   |  [Render pages] --> [Vision LLM] --> answers per question |
   |    MCQ    : question no. -> correct letter                |
   |    Theory : question no. -> mark scheme text (LaTeX)      |
   |          |                                                |
   |          v                                                |
   |  [Match answers to questions by number]                   |
   |  < All matched? > --No--> [Flag unmatched for review]     |
   +-----------------------------------------------------------+
          |
          v
   [Save in one DB transaction]
     questions, mcq_options, answers, question_assets,
     question_topics  (all status = IN_REVIEW)
          |
          v
   [Paper status = IN_REVIEW, progress 100%]
          |
          v
   [Notify uploader: "Ready for review"]

   ON FAILURE (any step):
   [BullMQ auto-retry with backoff (e.g. 3 tries)]
          |
          v
   < Still failing? > --Yes--> [Paper status = FAILED + error saved]
                               [Admin can "Re-process"]

   NOT IN PHASE 1 (placeholder):
   [Generate embeddings --> pgvector]   <-- added in Phase 2/3

   (S) Later: run multiple workers in parallel (more servers or
       containers). Same queue, same code. Add embeddings step
       as a new job type "embed-questions" - no change to
       existing steps.

   [Select SUBMITTED paper]
          |
          v
   [Review questions (same side-by-side screen)]
          |

          |
          +-- APPROVE ALL ----------------------------+
          |                                           |
          +-- APPROVE SOME + REJECT SOME              |
          |      |                                    |
          |      v                                    |
          |   [Rejected questions -> back to teacher  |
          |    with comment, status = REJECTED]       |
          |   [Approved questions continue] ----------+
          |                                           |
          +-- REJECT PAPER                            |
                 |                                    |
                 v                                    v
          [Paper status = REJECTED         [Status = APPROVED]
           + comment -> teacher fixes            |
           -> SUBMITTED again]                   v
                                          [Admin clicks PUBLISH]
                                                 |
                                                 v
                                          [Status = PUBLISHED]

                                          [Clear related cache]

   [PUBLISHED] --> [ARCHIVE] --> hidden from students, never deleted

11. SCALE PATH: PHASE 1 -> THOUSANDS OF USERS
=====================================================================

   PHASE 1 (~80 users)            PHASE 2 (~500-2,000)
   -------------------            --------------------
   1 server, all in Docker   -->  + CDN for images
   PostgreSQL in Docker      -->  Managed PostgreSQL (backups)
   Redis in Docker           -->  Managed Redis
   Worker on same server     -->  Worker on its own server
   No cache                  -->  Redis cache (topic tree, filters)
   Similar = topic match     -->  (optional) pgvector embeddings
   Basic logs                -->  Monitoring + error tracking

                                  PHASE 3 (5,000-10,000+)
                                  -----------------------
                             -->  Load balancer + 2..N API servers
                             -->  Multiple workers (parallel jobs)
                             -->  PostgreSQL read replica
                             -->  PgBouncer connection pooling
                             -->  Autoscaling for exam season
                             -->  (optional) RAG / AI explanation
                             -->  Analytics dashboards

   Phase 3 picture:

                      [CDN]
                        |
                 [Load Balancer]
                  /     |      \
            [API 1] [API 2] [API N]
                  \     |      /
        +-----------+---+--------+-----------+
        |           |            |           |
   [PostgreSQL] [Read       [Redis]      [S3 / R2]
    primary +    replica]   cache +
    pgvector                BullMQ
                               |
                     [Worker 1..N] --> [LLM API]
                                   --> [Embeddings API]


=====================================================================
12. RULES THAT KEEP PHASE 1 SCALABLE
=====================================================================
   (Follow these now -> scaling later = add servers, not rewrite)

   1. STATELESS API      : JWT auth, no data stored in server
                           memory or local disk.
   2. FILES IN STORAGE   : every PDF / image / worksheet in S3/R2,
                           DB stores only the file key/path.
   3. QUEUE FOR HEAVY WORK: PDF processing + PDF generation always
                           via BullMQ, never inside an HTTP request.
   4. ONE CODEBASE, MODULES: NestJS modular monolith; worker uses
                           the same code, started in worker mode.
   5. CONFIG IN .ENV     : DB URL, Redis URL, storage bucket, LLM
                           key, CDN domain -> change infra by
                           changing env only.
   6. MIGRATIONS         : every DB change through migrations.
   7. INDEXES FROM DAY 1 : papers(subject, year, season, paper_no),
                           questions(paper_id, status),
                           question_topics(topic_id).
   8. PAGINATION ALWAYS  : never return all rows.
   9. CACHE HOOKS        : "clear cache on publish" exists in code
                           from day 1 (empty now, Redis later).
  10. DOCKER EVERYTHING  : same containers run on 1 server or many.
  11. BACKUPS            : daily DB backup to storage from day 1.
  12. PROVENANCE ALWAYS  : every question linked to paper, page,
                           source PDF.
