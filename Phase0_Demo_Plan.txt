3. SIMILAR QUESTIONS WITHOUT VECTOR DB
---------------------------------------------------------------------
  YES, possible. For a demo it works well.

  Idea: at upload time AI already gives topic, subtopic and we also
  ask it for 5-10 CONCEPT KEYWORDS per question
  (e.g. "momentum", "elastic collision", "impulse").
  These are saved in MySQL. Then similarity = a scoring query.

  SCORE for each candidate question:
    + 5  same subtopic
    + 3  same topic
    + 2  per shared keyword
    + 1  same question type (MCQ/Theory)
    + 1  same difficulty
    + FULLTEXT relevance of question text (MySQL MATCH AGAINST)
  Show top 5, excluding the current question.

  Example SQL (simplified):

    SELECT q.id, q.question_number, p.year, p.season,
      ( (q.subtopic_id = :subtopicId) * 5
      + (q.topic_id    = :topicId)    * 3
      + (q.question_type = :type)     * 1
      + (q.difficulty    = :diff)     * 1
      + 2 * (SELECT COUNT(*) FROM question_keywords k
             WHERE k.question_id = q.id
               AND k.keyword IN (:keywordsOfCurrent))
      + MATCH(q.question_text) AGAINST (:currentText
             IN NATURAL LANGUAGE MODE)
      ) AS score
    FROM questions q
    JOIN papers p ON p.id = q.paper_id
    WHERE q.status = 'PUBLISHED'
      AND q.subject_id = :subjectId
      AND q.id <> :currentId
    ORDER BY score DESC
    LIMIT 5;

  Speed: precompute once on publish and save to a
  similar_questions table (question_id, similar_id, score)
  -> question page loads instantly.

  Limitation vs vectors: two questions with the same concept but
  totally different words AND different keywords may be missed.
  Fine for demo. Upgrade later (Section 10) without changing UI.

4. SEARCH (WITHOUT VECTOR DB)
---------------------------------------------------------------------
  - MySQL FULLTEXT index on question_text + answer_text + keywords
  - Search box -> MATCH ... AGAINST (natural language mode)
  - Combined with active filters (subject, topic, year...)
  - Results ranked by relevance; each result card has
    "Similar questions" link (Section 3)
  - Keyword table also matched -> searching "collision" finds
    questions tagged "elastic collision" even if text differs.

  MySQL notes:
  - Use InnoDB + utf8mb4 (LaTeX symbols, Arabic later)
  - Default min word length for InnoDB fulltext is 3 characters
    (short terms like "pH" need setting change or keyword table)

8. DATABASE (MYSQL, InnoDB, utf8mb4)
---------------------------------------------------------------------
  (Generic design - works for ANY curriculum, see Section 12)

  boards          (id, name, short_name)    Cambridge (CIE), Pearson
                                            Edexcel, IB, CBSE, MOE
  curriculums     (id, board_id, name, short_name, sort_order)
                                            "CIE AS Level", "CIE
                                            IGCSE", "Edexcel IAL"
  grades          (id, curriculum_id, name) OPTIONAL - for
                                            curriculums using
                                            Grade/Year/Standard
                                            (Grade 10, Year 11...)
  subjects        (id, curriculum_id, name, code)  Physics 9702
  components      (id, subject_id, number, name, question_style
                   ENUM('MCQ','THEORY','PRACTICAL','MIXED'),
                   total_marks, duration_min)
                   e.g. 1 = "Multiple Choice" (MCQ)
                        2 = "AS Structured Questions" (THEORY)
  seasons         (id, board_id, code, name, sort_order)
                   e.g. m = Feb/March, s = May/June, w = Oct/Nov
  topics          (id, subject_id, parent_id NULL, code, name,
                   sort_order)
                   parent_id NULL = topic, else = subtopic
                   code = syllabus number, e.g. topic "6" Dynamics,
                   subtopic "6.2" Momentum (verify vs syllabus)
  papers          (id, subject_id, component_id, year, season_id,
                   variant, paper_code (e.g. '11'),
                   source_file_name (e.g. '9702_s26_qp_11.pdf'),
                   ms_file_name (e.g. '9702_s26_ms_11.pdf'),
                   question_pdf_path, markscheme_pdf_path,
                   page_count, question_count, total_marks,
                   status ENUM('PROCESSING','IN_REVIEW','PUBLISHED',
                   'FAILED'), created_at, updated_at)
                   UNIQUE(subject_id, year, season_id, paper_code)
  paper_pages     (id, paper_id, page_number, image_path,
                   kind ENUM('QP','MS'))
  questions       (id, paper_id, subject_id, parent_id NULL,
                   question_number, question_type
                   ENUM('MCQ','THEORY','STRUCTURED'),
                   question_text TEXT, marks, topic_id, subtopic_id,
                   difficulty ENUM('EASY','MEDIUM','HARD'),
                   page_number, ai_confidence JSON,
                   status ENUM('DRAFT','VERIFIED','PUBLISHED'),
                   created_at, updated_at,
                   FULLTEXT(question_text))
  mcq_options     (id, question_id, label CHAR(1), option_text,
                   is_correct)
  answers         (id, question_id, answer_text TEXT,
                   mark_scheme_text TEXT, FULLTEXT(answer_text))
  question_images (id, question_id, image_path, page_number,
                   crop_box JSON, sort_order)
  question_keywords (question_id, keyword, INDEX(keyword))
  similar_questions (question_id, similar_question_id, score)
  processing_jobs (id, paper_id, status, progress, message, error,
                   created_at, updated_at)
  admin_users     (id, name, email, password_hash)

  Key indexes:
   questions(subject_id, status), questions(topic_id),
   questions(subtopic_id), questions(difficulty),
   papers(subject_id, year, season, paper_number)

  Files on disk (DB stores relative path only):
   /uploads/papers/{paperId}/qp.pdf, ms.pdf
   /uploads/pages/{paperId}/qp-p7.png
   /uploads/questions/{questionId}/img1.webp

9. STEP-BY-STEP BUILD ORDER
---------------------------------------------------------------------
  STEP 0  AI accuracy test (1-2 days)
          Run 3-5 real papers (1 Physics MCQ, 1 Physics theory,
          1 Biology) through the LLM prompt. Check text, LaTeX,
          crop box, topics. Decide how much editing is expected.

  STEP 1  Project setup
          GitLab repo, Next.js + NestJS, MySQL database + migrations,
          seed exam boards / levels / subjects / topic lists.

  STEP 2  Upload
          Password modal + JWT, upload form, save PDFs to disk,
          render pages to images, job status + progress UI.

  STEP 3  AI extraction
          Vision LLM per page -> JSON -> validation -> crop images
          -> mark scheme matching -> save as DRAFT.

  STEP 4  Editor
          Side-by-side editor, LaTeX live preview, crop tool,
          topic/subtopic/difficulty/keywords editing,
          [Regenerate with AI + hint], verify, publish.

  STEP 5  Student browse
          Filters (sidebar + mobile sheet), question list,
          question page, reveal answer, source info, image zoom.

  STEP 6  Search + Similar questions
          FULLTEXT search, keyword matching, similarity scoring,
          precompute on publish.

  STEP 7  Polish
          Responsive checks, skeleton loaders, performance,
          empty states, error messages, demo data (5-10 papers).

10. HOW PHASE 0 GROWS LATER (NO REWRITE)
---------------------------------------------------------------------
  Phase 0 (demo)             Later (Phase 1 -> thousands)
  -------------------------  -----------------------------------
  Local disk /uploads    --> S3 / R2 (swap StorageService class;
                             DB paths stay the same format)
  Background task in API --> BullMQ + Redis (swap JobService class)
  Admin password only    --> Users + roles (Super Admin, Admin,
                             Teacher, Student) + approval flow
  Similar via MySQL score--> + embeddings (MariaDB 11.7+ vector /
                             PostgreSQL pgvector / Qdrant);
                             same API + UI
  1 server               --> CDN, load balancer, more servers

  Rules followed from day 1 so this works:
  - All file access through ONE StorageService
  - All background work through ONE JobService
  - Config in .env (DB, storage path, LLM key)
  - Migrations for every DB change
  - REST API, stateless (JWT)

12. CURRICULUMS IN DUBAI (FLEXIBLE DB DESIGN)
---------------------------------------------------------------------
  Dubai private schools follow MANY curriculums. Most common
  (to be confirmed with client):
    - British   : Cambridge (CIE) IGCSE / AS / A Level,
                  Pearson Edexcel (IGCSE, International A Level),
                  AQA, OCR
    - IB        : MYP, Diploma Programme (DP)
    - American  : US curriculum, AP, SAT
    - Indian    : CBSE, CISCE (ICSE / ISC)
    - UAE MOE   : Ministry of Education curriculum
    - Others    : French, etc.
  British curriculum is the most common in Dubai private schools.

  Different curriculums use different words:
    Cambridge -> Level (IGCSE, AS, A Level), Paper, Variant,
                 Season (Feb/Mar, May/Jun, Oct/Nov)
    CBSE/ICSE -> Class/Standard (10, 12), Board exam, Set
    American  -> Grade (9-12), AP exam
    IB        -> SL / HL, Paper 1/2/3, Time zone

  So the DB is GENERIC (Section 8):
    Board -> Curriculum -> (optional Grade) -> Subject ->
    Component (paper type) -> Paper (year + season + variant)
    -> Question
  New curriculum later = add rows in admin, NO code change.
  Labels in UI (e.g. "Season" vs "Session", "Level" vs "Class")
  can come from the curriculum settings.

  Demo: CIE AS Level -> Physics (9702) (same as current screen).

13. CAMBRIDGE PAPER NAMING (AUTO-FILL FROM FILE NAME)
---------------------------------------------------------------------
  Cambridge file names already contain all paper info:

     9702 _ s26 _ qp _ 11 .pdf
      |      |    |    |
      |      |    |    +-- 11 = Paper 1, Variant 1
      |      |    |         (12 = Paper 1 Variant 2, 21 = Paper 2
      |      |    |          Variant 1, 42 = Paper 4 Variant 2)
      |      |    +------- qp = question paper
      |      |              ms = mark scheme
      |      |              (also in, gt, er exist - ignore for now)
      |      +------------ s = May/June (summer)
      |                     w = Oct/Nov (winter)
      |                     m = Feb/March
      |                     26 = year 2026
      +------------------- 9702 = subject code (Physics AS & A Level)

  -> On upload, the system PARSES the file name and auto-fills:
       Subject = Physics 9702, Season = May/June, Year = 2026,
       Paper = 1 (Multiple Choice), Variant = 1, Paper code = 11
     NO AI needed for this. Admin just confirms.
  -> Upload both files together (9702_s26_qp_11.pdf +
     9702_s26_ms_11.pdf) -> system pairs QP with MS automatically.
  -> Bulk upload (many files at once) becomes easy later.

  Physics 9702 components (for demo seed data, verify against
  the current Cambridge syllabus):
     Paper 1  Multiple Choice              (MCQ)
     Paper 2  AS Level Structured Questions (THEORY)
     Paper 3  Advanced Practical Skills     (PRACTICAL)
     Paper 4  A Level Structured Questions  (THEORY)
     Paper 5  Planning, Analysis and Evaluation (THEORY)
  Filter "Paper(s)" shows: Paper 1 - Multiple Choice, Paper 2 ...
  and can also filter exact code (11, 12, 13).

18. SIMILAR QUESTIONS: OPTIONS AND WHEN TO SWITCH
---------------------------------------------------------------------
  OPTIONS (all store results at publish time -> question page instant)

  1. Same topic / subtopic only
     Free, instant, no AI at view time. Weak: every question in the
     topic looks "similar", no ranking.

  2. Tags + keywords + MySQL FULLTEXT score   (current Phase 0 plan)
     Score = same subtopic +5, same topic +3, each shared keyword +2,
     same type +1, same difficulty +1, + text relevance.
     Free. Good while tags are consistent.

  3. Syllabus learning-outcome tags   (RECOMMENDED for exam papers)
     The syllabus lists numbered learning outcomes, e.g.
     "3.2(c) apply the principle of conservation of momentum".
     At upload the AI picks the outcome codes from this FIXED list
     (it cannot invent tags). Similar = shares the same outcome(s),
     ranked by option 2's score.
     Very accurate for exam questions, explainable to students
     ("Same syllabus point 3.2c"), free at view time, also gives
     topic analytics later. Needs the syllabus outcome list per
     subject (one-time data entry / AI-assisted from the syllabus PDF).

  4. AI re-ranking at publish time (no vector database)
     For each new question: take the top 20 candidates from option 2/3
     and ask the AI "which 5 test the same concept?". Store the 5.
     High quality, AI cost only once per question when publishing.

  5. Vector embeddings (meaning-based)
     Each question -> embedding (numbers) -> nearest questions.
     Finds same concept with completely different wording, works
     across boards (Cambridge <-> Edexcel), enables free-text
     semantic search. Needs embeddings API (very cheap) + vector
     support: MariaDB 11.7+ / PostgreSQL pgvector / Qdrant.

  6. Hybrid (best at large scale)
     Vector similarity + outcome/topic match + same type, with filters.

  7. Student behaviour ("students who practised this also did...")
     Needs many active students and attempt history. Later phase.

  WHEN IS EACH ENOUGH? (rough guide)
     Questions in bank      Recommended
     ---------------------  ------------------------------------------
     up to ~2,000           Option 2 or 3 (free). Option 4 for extra
     (demo, 1-3 subjects)   quality.
     ~2,000 - ~20,000       Option 3 (+4). Still fine if tags come from
     (several subjects)     a fixed syllabus list.
     ~20,000+ / many boards Option 5 or 6 (vectors / hybrid).

  The count is not the main trigger. Switch to vectors when ANY of:
     - tags become inconsistent and admins keep fixing similar lists
     - you want similar questions ACROSS boards (Cambridge vs Edexcel)
     - you want a free-text search box that understands meaning
       ("ball bounces off wall" finds "sphere rebounds from surface")
  Note: even 50,000 questions is small for vector search, so speed is
  not the issue; accuracy and features are.

  PLAN
     Phase 0 (demo): Option 3 if syllabus outcomes are available,
                     otherwise Option 2. Optional Option 4.
     Phase 2+:       add embeddings (Option 5/6) when a trigger above
                     happens. Same "Similar questions" UI, only the
                     scoring service changes.
